# KohliIQ — Venue Canonicalization (Phase 6.1)

## Why

Raw Cricsheet venue strings fragment physical grounds (`M Chinnaswamy
Stadium` vs `M Chinnaswamy Stadium, Bengaluru` vs `M.Chinnaswamy Stadium`),
so venue analytics split one ground into several rows. Canonicalization
regroups rows by verified physical venue. It changes grouping only —
innings, runs, dismissals, balls, and highest scores are untouched
(reconciliation below).

## Raw vs canonical identity

- **Raw** (`venues` table, immutable): one row per distinct
  (Cricsheet spelling, city) pair — 486 rows. Raw city NULLs are preserved
  as NULL; nothing is written back.
- **Canonical** (`canonical_venues`): one row per verified physical ground —
  319 rows: `canonical_key` (slug, UNIQUE), `canonical_name`, `city`
  (nullable), `country` (nullable where not reliably known).
- **Mapping** (`venue_aliases`): every raw row → exactly one canonical row,
  with `mapping_type`, `confidence` (high/medium), and an evidence `source`.
  Missing coverage fails ingestion loudly.

## Rules

1. No blind fuzzy merging. Same-base merges are mechanical
   (city-suffix/punctuation/case variants, null-city inheritance within a
   verified family); anything needing judgment is an explicit curated entry.
2. Historical renames merge only when documented: Feroz Shah Kotla →
   Arun Jaitley Stadium (2019); Sardar Patel Stadium, Motera → Narendra
   Modi Stadium (2021); Goodyear Park → Mangaung Oval; Chittagong
   Divisional Stadium → MA Aziz Stadium.
3. Same names, different grounds stay split: County Ground
   (Bristol/Taunton/Chelmsford), National Stadium (Hamilton/Karachi),
   Nehru Stadium (Guwahati/Kochi/Pune/Fatorda), Gymkhana Club Ground
   (Nairobi/Dar-es-Salaam).
4. Null city is never invented in raw data. A canonical city is assigned
   only through an explicit family mapping (e.g. null-city Sydney rows join
   the verified Sydney family); single-null rows with self-identifying
   names (Galle, Sheikhupura, …) are mapped with a stated source.
5. City renames use current official names (Bengaluru, Chattogram,
   Gqeberha); country comes from a curated city→country map, empty when
   unverified.

## Registry

`data/reference/venue_aliases.csv` (tracked) is authoritative:
`raw_venue_name, raw_city, canonical_venue_name, canonical_city,
canonical_country, mapping_type, confidence, source`, with
`mapping_type ∈ {EXACT, NORMALIZED_ALIAS, HISTORICAL_RENAME,
CURATED_ALIAS, UNRESOLVED}` (486 rows: 300 EXACT, 112 NORMALIZED, 68
CURATED incl. renames context, 6 HISTORICAL). It is generated by
`db/reference/build_venue_aliases.py` from venue rows + explicit curated
tables — no similarity scores decide merges. To add an alias safely:
verify the physical ground, add/adjust a family entry, regenerate,
review the CSV diff, run registry tests + ingestion + reconciliation.

## Reconciliation

`python -m db.reconcile` verifies: 486/486 alias coverage; canonical
batter-innings/runs/balls totals equal raw totals (119,619 / 2,350,638 /
2,368,673); Kohli canonical rows = 682 with runs equal to the raw sum.
`venue-summary` ordering is unchanged (runs DESC, innings ASC,
canonical name ASC).

## Limitations

- 15 medium-confidence mappings (shared associate namesakes’ grounds,
  metro tags like Toronto→King City, concurrent Wanderers spellings) —
  listed in the registry; challenge any of them with evidence.
- Canonical display names keep the most-used raw spelling (e.g. County
  Ground Chelmsford retains its suffix); identity is name+city, not the
  string alone.
